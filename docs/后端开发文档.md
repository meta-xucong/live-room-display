# 后端开发文档

## 1. 当前状态与边界

前端视觉原型已完成并确认。当前实现接入登录、Excel 上传与校验、SQLite 持久化、展示 API 和服务端校时，可在本机运行；尚未绑定或部署到用户的真实服务器。

管理员工作区沿用当前白色磨砂玻璃视觉基线；账号管理 UI、历史版本和审计查询不在第一版范围内。

第一版范围限定为：账号登录和角色鉴权、管理员上传并校验工作簿、用户选择直播间查看、按排班边界自动切换。第一版不包含账号管理页面、数据历史和回滚、审计查询。

## 2. 当前实现架构

采用单体 Web/API 服务：

```text
浏览器（展示页 / 管理员上传页）
        │ 同源 HTTPS / JSON API
        ▼
Node.js Web/API 服务 ───── SQLite（账号、会话、直播间、排班、商品和照片）
```

前端沿用 React/Vite；服务端使用 Node.js 24 HTTP 服务和内置 `node:sqlite`。第一版将照片以 BLOB 保存在 SQLite 文件中，媒体接口要求登录。数据库文件放在 `DATA_DIR` 指定的私有持久化目录。网页和 API 可由同一个 Node 服务提供，并通过 HTTPS 反向代理统一入口。

开发和生产环境使用不同配置。SQLite 文件放在项目之外的私有目录；登录密码不写入仓库、浏览器代码、日志或文档。

## 3. 数据模型

| 表 | 关键字段 | 用途 |
|---|---|---|
| `users` | `id`, `username`, `password_hash`, `role`, `enabled` | 登录账号；角色为 `admin` 或 `viewer`。 |
| `sessions` | `token_hash`, `user_id`, `csrf_token`, `expires_at` | 服务端登录会话；数据库保存会话令牌的哈希。 |
| `rooms` | `code`, `name`, `sheet_name`, `sort_order` | 当前有效工作簿里的直播间；`code` 唯一。 |
| `slots` | `id`, `room_code`, `date`, `start_time`, `end_time`, `starts_at`, `ends_at`, 岗位和排班字段 | 当前排班；按 `Asia/Shanghai` 解释并存为时间点。商品以 JSON 顺序数组保存。 |
| `slots` 照片字段 | `photo_type`, `photo_blob` | 照片与排班一同保存在私有 SQLite 文件中，通过登录保护的媒体接口读取。 |
| `app_state` | `key`, `value` | 当前排班数据更新时间。 |

导入问题作为上传接口的响应返回，不要求另建历史问题表。当前工作簿数据直接保存在房间、排班、商品和图片记录中。

### 3.1 约束

- 导入全部校验通过后，在一个数据库事务中整体替换当前房间、排班及商品数据；事务失败时旧数据不变。
- `starts_at < ends_at`。跨午夜排班在导入时把结束时间解析到次日。
- 同一房间的排班区间不得重叠；由导入服务按完整时间区间校验。
- 目标金额以“分”为整数保存，避免浮点金额累积误差。
- 照片允许 JPG/PNG，直接以二进制内容保存；上传文件名不作为存储路径。

## 4. API 契约

接口统一使用 `/api/v1`、HTTPS、JSON。会话使用服务端会话标识和 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax` 的 Cookie；写操作校验 CSRF。常规 API 错误响应格式：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "工作簿有 2 项需要修正",
    "details": []
  }
}
```

### 4.1 认证

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `POST /api/v1/auth/login` | 未登录 | 校验账号并建立会话。 |
| `GET /api/v1/auth/me` | 已登录 | 返回用户 ID、用户名和角色。 |
| `POST /api/v1/auth/logout` | 已登录 | 使当前会话失效并清除 Cookie。 |

登录错误统一返回，不透露用户名是否存在。密码使用 `scrypt` 哈希保存，禁止明文或可逆加密。

### 4.2 展示端

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `GET /api/v1/rooms` | 已登录 | 返回直播间编号、名称和排序。 |
| `GET /api/v1/rooms/{roomCode}/display` | 已登录 | 返回服务器当前时间、房间、今天及昨天的排班、下一时间边界和照片地址；页面根据服务器时间偏移确定当前/下一时段。 |
| `GET /api/v1/rooms/{roomCode}/schedule?date=YYYY-MM-DD` | 已登录 | 返回指定日期的排班。 |
| `GET /api/v1/media/{slotId}` | 已登录 | 校验会话后读取指定排班照片。 |

`display` 响应示例（时间戳为毫秒）：

```json
{
  "dataUpdatedAt": "2026-11-12T01:00:00.000Z",
  "serverNow": "2026-11-12T01:15:00.000Z",
  "timeZone": "Asia/Shanghai",
  "room": { "code": "01", "name": "服饰直播间" },
  "schedule": [{
    "id": "0123456789abcdef0123456789abcdef",
    "date": "2026-11-12",
    "start": "07:00",
    "end": "11:00",
    "startsAt": 1794438000000,
    "endsAt": 1794452400000,
    "director": "示例导演",
    "host": "示例主播",
    "assistant": "示例助播",
    "photo": "/api/v1/media/0123456789abcdef0123456789abcdef",
    "featuredProducts": ["商品示例 A", "商品示例 B"],
    "salesTarget": "20万元"
  }],
  "nextTransitionAt": 1794452400000
}
```

页面使用 `startsAt <= serverNow < endsAt`；无当前时段时展示之后最早的一场。`schedule` 包含今天和昨天的排班，以支持跨午夜场次。未配置照片时 `photo` 为 `null`。

### 4.3 管理端

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `POST /api/v1/admin/schedule-upload` | 管理员 | 上传 `.xlsx`；校验通过后整体更新当前排班；校验失败时返回逐表逐行问题且不改当前数据。 |

上传响应包含处理结果、直播间/排班数量、错误及警告。服务端必须验证管理员角色；前端隐藏上传按钮不构成权限控制。校验失败返回 HTTP 422 及按工作表、行和字段定位的 `errors`。

## 5. Excel 导入处理

### 5.1 流程

1. 验证登录会话及管理员角色。
2. 只接受 `.xlsx`；限制请求大小及压缩包展开大小；拒绝损坏、加密、带宏或包含外部链接的工作簿。
3. 解析工作簿各表：读取直播间元信息、表头、排班行和锚定于对应行的图片。
4. 验证图片为 JPG 或 PNG，单张不超过 8 MB，并按工作表及排班行关联。
5. 返回工作簿摘要、错误和警告。存在阻断错误时不修改当前数据。
6. 校验通过后，在一个数据库事务中替换当前房间、排班及商品信息；成功后返回更新结果。

### 5.2 阻断错误

- 工作簿无法读取或没有有效直播间工作表。
- 直播间编号/名称缺失，或工作簿内编号重复。
- 日期、开始时间、结束时间缺失或无法识别。
- 排班时长为零，或同一直播间排班重叠。
- 图片损坏、无法安全解码或不能关联到唯一排班行。
- 商品或金额有非空值但无法解析。

可选岗位、照片、主推商品和目标金额允许为空并显示提示，不阻止更新。

## 6. 时间计算与自动刷新

后端按 `Asia/Shanghai` 把 Excel 日期/时间转换成带时区时间。排班开始包含、结束不包含；若结束时间早于开始时间，结束日期加一天；若相同则视为无效。

显示接口返回 `serverNow` 和下一次排班边界。浏览器按边界设置定时刷新，并最多每 30 秒检查一次数据是否更新；页面回到前台或网络恢复时立即重取。每次边界刷新都请求服务端数据重新判定，不让浏览器独自决定实际人员。

服务端无需为每个浏览器维护定时任务；API 返回服务器时刻和排班时间边界，浏览器据此确定当前场次并在边界重取数据。

## 7. 登录与文件安全

- 账号角色为 `admin`、`viewer`；第一版不开放注册或账号管理页面，账号通过 `npm run create-user` 交互式创建。
- 密码使用 Node `scrypt` 强哈希保存；初始化密码至少 12 位，不设公开默认密码。
- 会话 Cookie 使用 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax`，有效期为 12 小时。
- 同一账号 15 分钟内最多 8 次失败登录；同一管理员 10 分钟内最多上传 8 次工作簿；写请求校验 CSRF。
- 上传只接受 `.xlsx`；不把公式作为数据读取、不加载外链、不解析宏；限制压缩包展开大小和图片尺寸，文件名作为普通文本处理。
- 页面内容转义显示；工作簿公式不作为 HTML 或可执行内容写入页面。
- 照片通过登录校验的媒体接口读取，不生成公开链接。
- 服务端错误日志不写入密码、Cookie、访问密钥或照片内容。

## 8. 数据同步

- 展示接口返回当前数据更新时间；页面每 30 秒检查更新，并在临近排班边界时触发刷新。
- 读取失败时保留最后一次成功展示；网络恢复或页面重新显示时立即重试。
- 导入校验错误由接口返回到管理员页面；服务端仅记录导入更新失败的简要错误信息。

## 9. 实施状态

本地第一版已包含登录与角色鉴权、管理员工作簿上传、字段和时间冲突校验、事务式替换、直播间展示 API、登录保护的照片读取及自动切换。账号创建和服务运行方式见 `README.md`。用户的服务器、域名、HTTPS 反向代理和持久化目录尚未配置。

## 10. 部署前工作

- 确认服务器系统、运行方式、域名及 HTTPS 反向代理。
- 为 `DATA_DIR` 配置服务器私有持久化目录及备份策略。
- 在目标服务器创建管理员和普通用户账号。
- 使用合成排班完成部署验收后，再上传真实工作簿。

## 11. 验收清单

- 普通用户不能调用管理上传接口；未登录用户不能读取排班或照片。
- 每个工作表解析成一个直播间；同一表的多行解析成多场；图片关联到正确行。
- 错误定位包含工作表、行和字段；阻断错误不会改动当前数据。
- 上传有效工作簿后所有房间数据一次性更新，不出现部分房间新旧混杂。
- 开始/结束边界、相邻场、空档、跨午夜和次日排班判断正确。
- 页面自动切换；新工作簿上传成功后 30 秒内可见；短暂断网时保留上次数据。
- 照片可被已登录用户访问，未登录请求被拒绝；无照片时显示现有占位。
- 生产环境启用 HTTPS，仓库中没有真实排班资料和凭据。
