# 后端开发文档

## 1. 当前状态与边界

前端视觉原型已完成并确认。当前实现接入登录、Excel 上传与校验、SQLite 持久化、展示 API、Harness 文本排班 API 和服务端校时，生产环境通过 Nginx 与 HTTPS 提供服务。

管理员工作区沿用当前白色磨砂玻璃视觉基线；账号管理 UI、历史版本和审计查询不在第一版范围内。

第一版范围限定为：账号登录和角色鉴权、管理员上传并校验工作簿、用户选择直播间查看、按排班边界自动切换。第一版不包含账号管理页面、数据历史和回滚、审计查询。

## 2. 当前实现架构

采用单体 Web/API 服务：

```text
浏览器（展示页 / 管理员上传页）
        │ 同源 HTTPS / JSON API
        ▼
Node.js Web/API 服务 ───── SQLite（账号、会话、直播间、排班、商品和照片）
```

前端沿用 React/Vite；服务端使用 Node.js 24 HTTP 服务和内置 `node:sqlite`。第一版将照片以 BLOB 保存在 SQLite 文件中，媒体接口要求登录。数据库文件放在 `DATA_DIR` 指定的私有持久化目录。网页和 API 可由同一个 Node 服务提供，并通过 HTTPS 反向代理统一入口。

开发和生产环境使用不同配置。SQLite 文件放在项目之外的私有目录；登录密码不写入仓库、浏览器代码、日志或文档。

## 3. 数据模型

| 表 | 关键字段 | 用途 |
|---|---|---|
| `users` | `id`, `username`, `password_hash`, `role`, `enabled` | 登录账号；角色为 `admin` 或 `viewer`。 |
| `sessions` | `token_hash`, `user_id`, `csrf_token`, `expires_at` | 服务端登录会话；数据库保存会话令牌的哈希。 |
| `rooms` | `code`, `name`, `sheet_name`, `sort_order` | 当前有效工作簿里的直播间；`code` 唯一。 |
| `room_identities` | `room_code`, `id`, `legacy_code` | 用稳定标识维持展示端选中的房间。`legacy_code` 用于迁移升级前保存的房号。 |
| `room_avatars` | `room_code`, `photo_type`, `photo_blob`, `version` | 直播间头像。房间删除时同步删除头像。 |
| `slots` | `id`, `room_code`, `date`, `start_time`, `end_time`, `starts_at`, `ends_at`, `host`, `assistant` 等 | 主播场次；时间独立校验。商品以 JSON 顺序数组保存。旧 `director` 字段仅为兼容保留，新写入不使用。 |
| `director_shifts` | `id`, `room_code`, `date`, `start_time`, `end_time`, `starts_at`, `ends_at`, `director` | 导演班次；与主播场次独立存储、校验和切换。 |
| `slots` 照片字段 | `photo_type`, `photo_blob` | 照片与排班一同保存在私有 SQLite 文件中，通过登录保护的媒体接口读取。 |
| `host_avatars` | `id`, `name`, `name_key`, `photo_type`, `photo_blob`, `photo_hash`, 时间戳 | 主播头像档案；`name_key` 经 Unicode NFKC、去空白和小写规范化后唯一，用于跨直播间匹配头像。 |
| `app_state` | `key`, `value` | 当前排班数据更新时间。 |

导入问题作为上传接口的响应返回，不要求另建历史问题表。当前工作簿数据直接保存在房间、排班、商品和图片记录中。

### 3.1 约束

- Excel 导入仅更新工作簿中的直播间和有排班行的日期；日期任一角色表有记录时，同日导演班次与主播场次一起整体替换；通过预览确认后，在一个数据库事务中写入；未出现的数据不变，事务失败时旧数据不变。
- `starts_at < ends_at`。跨午夜排班在导入时把结束时间解析到次日。
- 同一房间同一角色的区间不得重叠；导演与主播之间允许交叉，由导入服务分别校验。
- 目标金额以“分”为整数保存，避免浮点金额累积误差。
- 照片允许 JPG/PNG，直接以二进制内容保存；上传文件名不作为存储路径。

## 4. API 契约

接口统一使用 `/api/v1`、HTTPS、JSON。会话使用服务端会话标识和 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax` 的 Cookie；写操作校验 CSRF。常规 API 错误响应格式：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "工作簿有 2 项需要修正",
    "details": []
  }
}
```

### 4.1 认证

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `POST /api/v1/auth/login` | 未登录 | 校验账号并建立会话。 |
| `GET /api/v1/auth/me` | 已登录 | 返回用户 ID、用户名和角色。 |
| `POST /api/v1/auth/logout` | 已登录 | 使当前会话失效并清除 Cookie。 |

登录错误统一返回，不透露用户名是否存在。密码使用 `scrypt` 哈希保存，禁止明文或可逆加密。

### 4.2 展示端

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `GET /api/v1/rooms` | 已登录 | 返回连续的当前房号、从 0 开始的 `sortOrder`、稳定的 `roomId` 和用于升级的 `legacyCode`。无头像时 `avatarUrl` 为 `null`。 |
| `GET /api/v1/rooms/{roomCode}/avatar` | 已登录 | 返回直播间头像图片。未配置时返回 404。 |
| `GET /api/v1/rooms/{roomCode}/display` | 已登录 | 返回服务器当前时间、房间、今天及昨天的 `schedule`（主播场次）、`directorShifts`（导演班次）、最早的下一角色时间边界和照片地址。 |
| `GET /api/v1/rooms/{roomCode}/schedule?date=YYYY-MM-DD` | 已登录 | 返回指定日期的主播 `schedule` 与 `directorShifts`。 |
| `GET /api/v1/media/{slotId}` | 已登录 | 校验会话后读取指定排班照片。 |
| `GET /api/v1/host-avatars/{avatarId}/media` | 已登录 | 校验会话后读取头像库图片。 |

`display` 响应示例（时间戳为毫秒）：

```json
{
  "dataUpdatedAt": "2026-11-12T01:00:00.000Z",
  "serverNow": "2026-11-12T01:15:00.000Z",
  "timeZone": "Asia/Shanghai",
  "room": { "code": "01", "name": "服饰直播间" },
  "schedule": [{
    "id": "0123456789abcdef0123456789abcdef",
    "date": "2026-11-12",
    "start": "07:00",
    "end": "11:00",
    "startsAt": 1794438000000,
    "endsAt": 1794452400000,
    "host": "示例主播",
    "assistant": "示例助播",
    "photo": "/api/v1/media/0123456789abcdef0123456789abcdef",
    "featuredProducts": ["商品示例 A", "商品示例 B"],
    "salesTarget": "20万元"
  }],
  "directorShifts": [{
    "id": "abcdef0123456789abcdef0123456789",
    "date": "2026-11-12",
    "start": "07:00",
    "end": "13:00",
    "startsAt": 1794438000000,
    "endsAt": 1794459600000,
    "director": "示例导演"
  }],
  "nextTransitionAt": 1794452400000
}
```

前端对 `schedule` 和 `directorShifts` 分别按 `startsAt <= serverNow < endsAt` 计算当前和下一时段，任一角色到达边界都会刷新。两个列表包含今天和昨天的记录，以支持跨午夜场次。主播照片、商品与目标金额跟随主播场次；助播也跟随主播。

### 4.3 管理端

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `GET /api/v1/admin/schedule-upload/rooms` | 管理员 | 返回 01–27 号及已录入的直播间名称。 |
| `GET /api/v1/admin/rooms` | 管理员 | 列出已创建的直播间、头像、排班数量和 `dataUpdatedAt`。 |
| `PATCH /api/v1/admin/rooms/{roomCode}` | 管理员 + CSRF | JSON 传 `name`。保留直播间编号和排班。旧名称在匹配无歧义时继续用作 Excel 别名。 |
| `PUT /api/v1/admin/rooms/{roomCode}/avatar` | 管理员 + CSRF | 请求体传 JPG 或 PNG 图片原始字节，上限 8 MB。 |
| `DELETE /api/v1/admin/rooms/{roomCode}/avatar` | 管理员 + CSRF | 移除直播间头像，展示端使用默认头像。 |
| `DELETE /api/v1/admin/rooms/{roomCode}` | 管理员 + CSRF | 删除直播间及其头像、Excel 别名和全部关联排班。后面的房号及关联记录在同一事务内前移。 |
| `POST /api/v1/admin/rooms/{roomCode}/merge` | 管理员 + CSRF | JSON 传合并前的目标房号 `targetCode`。事务迁移排班、别名及可保留的头像，再排为连续房号。存在同角色时段重叠或两张不同头像时返回 409。 |
| POST /api/v1/admin/schedule-upload?action=preview&mode=room-name | 管理员 + CSRF | 上传员工 Excel，可附名称对应的 roomBindings。返回 needs_mapping 或 ready。 |
| POST /api/v1/admin/schedule-upload?action=commit&mode=room-name | 管理员 + CSRF | JSON 传 previewId，事务式写入预览列出的房间和日期。 |
| `GET /api/v1/admin/host-avatars` | 管理员 | 返回头像档案、排班引用数、头像统计和未统一的历史图片冲突。 |
| `POST /api/v1/admin/host-avatars` | 管理员 + CSRF | 批量上传 JPG/PNG；姓名已存在时需先确认替换，随后更新统一头像。 |
| `PATCH /api/v1/admin/host-avatars/{avatarId}` | 管理员 + CSRF | 提交新 `name` 和编辑前的 `expectedName`。在同一事务更新档案和关联排班姓名，返回更新的排班数。姓名冲突或档案已改名时返回 409。 |
| `DELETE /api/v1/admin/host-avatars/{avatarId}` | 管理员 + CSRF | 移除头像图片但保留主播档案；有关联的排班显示无头像占位。 |
| `DELETE /api/v1/admin/host-avatars/{avatarId}/profile` | 管理员 + CSRF | 提交确认时的 `expectedName`。删除档案和头像，保留关联排班并停用旧照片。后续排班导入会跳过档案的自动创建。 |

直播间管理的写请求通过 `If-Match` 传入用双引号包裹的 `dataUpdatedAt`。版本变化时返回 409，管理员重新核对后可再次操作。

### 4.4 Harness 文本接口

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `POST /api/v1/integrations/schedule-text/preview` | Bearer API 密钥 | 解析固定中文字段文本并校验；只返回预览，不写数据库。 |
| `POST /api/v1/integrations/schedule-text/commit` | Bearer API 密钥 | 必须带 `confirmReplace: true`；在事务中替换指定日期的完整导演班次和主播场次。 |

每次请求只包含一个直播间和一个日期。导演、主播时间分开校验；助播跟随主播。更新不会改变其他直播间或其他日期。校验同时检查各角色的跨午夜排班与前后日期冲突。照片不由文本接口上传；展示端优先按规范化主播姓名匹配统一头像库，未匹配时沿用相同主播时段的旧照片。新增或更换头像由管理员在头像库页面完成。固定输入格式和 OpenAPI 说明见 `docs/harness-api.md` 与 `docs/harness-openapi.yaml`。

API 密钥由 `scripts/create-api-token.mjs` 生成，数据库只保存 SHA-256 摘要，密钥只在创建时显示一次。每把密钥每 10 分钟最多调用 30 次，使用 `scripts/revoke-api-token.mjs` 撤销。

上传响应包含处理结果、直播间/排班数量、错误及警告。服务端必须验证管理员角色；前端隐藏上传按钮不构成权限控制。校验失败返回 HTTP 422 及按工作表、行和字段定位的 `errors`。

## 5. Excel 导入处理

1. 校验管理员会话、CSRF、文件大小及 .xlsx 工作簿结构。
2. 通过表头读取房间、日期和两类角色排班，校验工作簿内及未更新日期内的时间冲突。
3. 精确匹配已登记名称或别名。待匹配项由管理员指定对应编号并重新生成预览。
4. 按「房间编号 × 日期」汇总原有和导入后的清单。预览凭证绑定用户、内容和当前排班版本，10 分钟内有效。
5. 确认时在一个事务里保存新房间、别名和排班。相同主播时段保留原有扩展资料。重复提交同一凭证可在 24 小时内读取原结果。

校验失败返回 422，正文带可定位到工作表及行列的 errors。预览版本变化或过期返回 409。详情见 [员工排班表导入 · 前端开发文档](./员工排班表导入-前端开发文档.md)。

## 6. 时间计算与自动刷新

后端按 `Asia/Shanghai` 把 Excel 日期/时间转换成带时区时间。排班开始包含、结束不包含；若结束时间早于开始时间，结束日期加一天；若相同则视为无效。

显示接口返回 `serverNow` 和导演、主播下一边界中的最早值。浏览器分别计算两个角色当前/下一班次，在任一边界刷新；并最多每 30 秒检查一次数据是否更新。页面回到前台或网络恢复时立即重取。

服务端无需为每个浏览器维护定时任务；API 返回服务器时刻和两类排班时间边界，浏览器据此确定当前人员并在边界重取数据。

## 7. 登录与文件安全

- 账号角色为 `admin`、`viewer`；第一版不开放注册或账号管理页面，账号通过 `npm run create-user` 交互式创建。
- 密码使用 Node `scrypt` 强哈希保存；初始化密码至少 12 位，不设公开默认密码。
- 会话 Cookie 使用 `HttpOnly`、生产环境 `Secure`、`SameSite=Lax`，有效期为 12 小时。
- Harness 使用高熵 Bearer API 密钥；仅 Harness 集成路由接受密钥，浏览器会话不能替代 API 密钥。密钥以 SHA-256 摘要保存，丢失后重新创建，泄露后撤销。
- 同一账号 15 分钟内最多 8 次失败登录；同一管理员 10 分钟内最多上传 8 次工作簿；写请求校验 CSRF。
- 文本接口限制 60,000 字符、最多 100 个时段；预览无副作用，提交需显式确认替换，并通过 SQLite 事务写入。
- 上传只接受 `.xlsx`；不把公式作为数据读取、不加载外链、不解析宏；限制压缩包展开大小和图片尺寸，文件名作为普通文本处理。
- 页面内容转义显示；工作簿公式不作为 HTML 或可执行内容写入页面。
- 照片通过登录校验的媒体接口读取，不生成公开链接。
- 服务端错误日志不写入密码、Cookie、访问密钥或照片内容。

## 8. 数据同步

- 展示接口返回当前数据更新时间；页面每 30 秒检查更新，并在临近排班边界时触发刷新。
- 读取失败时保留最后一次成功展示；网络恢复或页面重新显示时立即重试。
- 导入校验错误由接口返回到管理员页面；服务端仅记录导入更新失败的简要错误信息。

## 9. 实施状态

当前实现包含登录与角色鉴权、管理员按直播间名称批量预览上传、字段和时间冲突校验、按房间和日期事务式更新、直播间展示 API、登录保护的照片读取、自动切换、Harness 固定格式文本接口，以及远程 MCP 工具和 Codex/WorkBuddy Connector 包。生产服务器、域名、HTTPS 反向代理和私有 SQLite 持久化目录已配置。

MCP 使用无会话 Streamable HTTP，沿用 `api_tokens` Bearer 密钥和每密钥限流。只读工具列出直播间和读取排班；写入工具支持单直播间单日期和单直播间多日期，先创建绑定密钥的一次性预览凭证，再由用户明确确认后提交。预览凭证 10 分钟过期、一次使用，且 `data_updated_at` 发生变化后拒绝提交。所有写入在 SQLite `BEGIN IMMEDIATE` 事务中完成。

## 10. 部署前工作

- 为 `DATA_DIR` 配置服务器私有持久化目录及备份策略。
- 按需创建管理员、普通用户账号和 Harness API 密钥。
- 将每日真实排班上传至系统；当前服务器示例数据仅用于演示。

## 11. 验收清单

- 普通用户不能调用管理上传接口；未登录用户不能读取排班或照片。
- 每个工作表解析成一个直播间；同一表的多行解析成多场；图片关联到正确行。
- 错误定位包含工作表、行和字段；阻断错误不会改动当前数据。
- 上传有效工作簿后所有房间数据一次性更新，不出现部分房间新旧混杂。
- 开始/结束边界、相邻场、空档、跨午夜和次日排班判断正确。
- 页面自动切换；新工作簿上传成功后 30 秒内可见；短暂断网时保留上次数据。
- 照片可被已登录用户访问，未登录请求被拒绝；无照片时显示现有占位。
- 生产环境启用 HTTPS，仓库中没有真实排班资料和凭据。

## 12. 部署前待确认

1. 服务器系统、部署方式、域名和是否与现有网站共用入口。
2. SQLite 私有持久化目录和备份方式。
3. 服务器上管理员和普通用户账号的配置安排。
