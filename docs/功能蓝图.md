# 直播间信息展示系统功能蓝图

## 1. 目标

为直播间门口电子屏提供网页展示页。管理员通过 Excel 维护直播间及分时排班；登录用户选择直播间后查看页面。页面根据当前时间自动展示对应时段、岗位人员和主播照片。

展示页视觉稿已确认。第一版程序已接入登录、管理员 Excel 上传、导入校验、排班展示和自动切换；目前可本地运行，尚未绑定真实服务器或部署。

## 2. 已确认的产品要求

- 一个 Excel 工作簿包含多个工作表；每个工作表代表一个直播间。
- 管理员可通过新增工作表增加直播间，并上传工作簿更新资料。
- 登录用户分管理员和普通用户：管理员负责上传资料，普通用户选择直播间查看。
- 页面展示直播间名称、当日排班、导演/主播/助播、主播照片、主推商品和目标销售额。
- 到达排班时间边界后，自动切换到对应时段、岗位人员及主播照片。
- 视觉基线已确认：白色半透明磨砂玻璃、轻奢、科技感、整洁；优先使用苹方字体，并保留系统中文无衬线字体回退。
- 公开仓库只包含合成示例；真实排班和人员资料由登录后的系统管理。

## 3. 用户角色与权限

| 角色 | 能力 |
|---|---|
| 管理员 | 登录、上传 `.xlsx`、查看导入校验结果；校验通过后更新当前排班数据。 |
| 普通用户 | 登录、查看直播间列表、选择直播间、查看当前和当日排班信息。 |

第一版只包含登录和角色鉴权，不提供账号管理页面或自助注册；初始账号在部署时安全配置。所有普通用户可查看全部直播间。

## 4. 核心页面与流程

### 4.1 登录页

- 使用用户名和密码登录。
- 登录成功后，管理员进入上传工作区，普通用户进入展示页。
- 登录失败显示简明提示；不说明用户名是否存在。

### 4.2 管理员上传工作区

- 上传 `.xlsx` 工作簿。
- 上传后显示直播间数量、排班数量、错误和警告，并指出对应工作表、行和字段。
- 全部校验通过后，系统一次性替换当前排班数据；校验失败则保留当前展示数据。

### 4.3 直播间展示页

- 标题栏内提供紧凑的直播间选择器。
- 页面展示时间、当日排班、直播间名称、当前或下一场时段、岗位人员、主播照片、主推商品和目标销售额。
- 当前时段使用“开始时间包含、结束时间不包含”的规则；无当前直播时显示下一场；当天没有可展示排班时显示空状态。
- 到达排班边界自动刷新；管理员上传有效工作簿后，打开中的页面在短时间内取得新数据。
- 沿用已通过的响应式和 F11 全屏布局，后端接入不改变视觉方向。

## 5. Excel 工作簿约定

第一版统一使用 `.xlsx`。每个工作表对应一个直播间。工作表名称供管理员辨认；表内直播间编号作为稳定标识，避免重命名工作表后被误认为新房间。

建议固定版式：

| 位置 | 内容 |
|---|---|
| B1 | 直播间名称（必填） |
| E1 | 直播间编号（必填，工作簿内唯一） |
| 第 4 行起 | 一行一场排班；同一直播间可填写多个时段和日期 |
| 排班列 | 日期、开始时间、结束时间、导演、主播、助播、主播照片、主推商品、目标销售额、备注 |

字段规则：

- 日期、开始时间、结束时间使用 Excel 日期/时间单元格；文字日期仅接受模板注明格式。
- 导演、主播、助播允许为空；为空时页面展示“待安排”。
- 主播照片嵌入到该场排班对应的“主播照片”单元格区域，不使用外部链接；系统按图片锚点所在行归属排班。
- 主推商品单元格可填多行，每行一个商品；空值表示没有配置。
- 目标销售额允许填数值或明确单位金额文字，如 `200000`、`20万`、`20万元`；导入后统一存为人民币金额。
- 备注只供后台管理，不出现在电子屏。
- 日期对应排班开始日；结束时间早于开始时间时按次日计算。开始和结束时间相同视为无效排班。
- 同一直播间的排班不得重叠；空档允许。跨午夜排班按实际区间检查。
- 直播间编号重复、必填字段缺失、日期或时间无法识别、排班冲突或照片无法解析时，拒绝本次更新。
- 可选岗位、照片、商品或目标金额为空时给出警告，但允许更新。

导入器按表头名称读取，不依赖列字母；房间信息单元格和表头位置固定为第一版模板的一部分。

## 6. 自动切换规则

- 系统时区为 `Asia/Shanghai`；API 同时返回服务器时间，浏览器时间不作为唯一权威时间。
- 排班按 `start <= now < end` 计算；相邻排班在边界点直接切换。
- 跨午夜排班的结束时间归属次日。查找当前场次时同时检查今天开始的排班和昨天开始且仍未结束的排班。
- 展示页在下一排班边界触发数据刷新，并最多每 30 秒检查一次数据更新；从后台标签恢复或网络恢复时立即重取。
- 边界刷新由服务器返回的最新数据重新判定，不依赖浏览器自行修改排班内容。
- 无当前场次时显示最近的下一场；没有剩余排班时显示空状态。

## 7. 数据更新与异常

- 工作簿先在临时处理中完成读取和校验；校验通过后，通过一个数据库事务整体替换当前排班。
- 上传或校验失败不修改线上展示数据；展示端网络短暂中断时保留最后一次成功读取的数据，并在恢复后重试。
- 登录失效、无权限、直播间不存在和网络异常均给出可理解状态。

## 8. 第一版范围

第一版只实现登录与角色鉴权、管理员上传 `.xlsx`、导入校验、直播间列表、展示数据接口、主播照片安全读取和按时间边界切换。账号管理页面、历史版本与回滚、审计查询不纳入第一版。

第一版不连接抖音直播实时数据、不采集实际成交额、不做库存/商品管理、不做多组织隔离、不自动读取外部表格链接。目标销售额是排班信息，不是实际销售统计。

## 9. 当前实现说明

- 管理员和普通用户通过部署时创建的账号登录；没有公开注册和账号管理页面。
- 管理员上传 `.xlsx` 后，服务端逐表读取并校验。全部通过后在 SQLite 事务中整体替换；失败时不改现有排班。
- 展示端按 `Asia/Shanghai` 获取时间和排班；到下一场边界刷新，并每 30 秒检查数据更新。
- 主播照片保存在服务端 SQLite 数据文件中，通过登录会话保护的媒体接口读取。
- 服务端使用 Node.js 24 和 Node 内置 SQLite；部署时需配置 HTTPS 反向代理及私有持久化目录。

## 10. 验收标准

1. 管理员上传符合模板的工作簿后，能看到全部工作表对应的直播间和排班数量。
2. 重复直播间编号、重叠排班、缺失直播间名称或无法读取照片时，能定位工作表、行和字段并拒绝更新。
3. 校验失败不改变当前排班；校验通过后一次性替换所有直播间数据。
4. 普通用户不能上传；未登录用户不能读取排班和照片。
5. 登录用户能选择直播间并查看当前时段、当日排班、人员、照片、商品和目标金额。
6. 排班开始、结束、相邻时段、空档和跨午夜场次切换正确，无需手动刷新。
7. 管理员上传成功后，已打开页面在 30 秒内取得更新；短暂断网不会清空旧展示。
