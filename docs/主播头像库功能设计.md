# 主播头像库功能设计

**状态：第一版已实现；扩展项见第 10 节。**

## 1. 设计目标

管理员集中上传和维护主播头像。员工通过 MCP 写入排班时，系统根据主播身份自动关联头像；展示页继续按当前时段显示主播和对应照片。管理员也能随时查看、搜索和更换头像。

设计原则：

- 一个主播维护一份常用头像，供多个直播间和排班时段复用。
- MCP 排班仍以文字为主，普通员工不需要每次重复上传图片。
- 头像库有独立管理页面，上传、替换和删除均由管理员操作。
- 现有排班和 Excel 照片保持兼容，迁移过程中不让已展示头像突然消失。

## 2. 管理员页面

在现有管理员工作区增加导航：

- **排班 Excel**：保留当前工作簿导入功能。
- **主播头像库**：新增头像管理页面。

头像库页顶部显示主播档案总数、有头像人数和待补头像人数。主体提供姓名搜索和批量上传入口。

头像列表显示：

| 内容 | 用途 |
| --- | --- |
| 头像缩略图 | 快速确认照片是否正确 |
| 主播姓名 | 确认匹配对象 |
| 使用情况 | 显示引用该头像的排班数量 |
| 更新时间 | 判断照片是否为最新 |
| 操作 | 编辑姓名、查看大图、更换头像、移除头像、删除主播 |

头像以卡片列表展示，点击缩略图可放大预览；卡片显示主播姓名、引用排班数量和最近更新时间，可直接更换或移除照片。更换时会显示覆盖影响，移除前会提示受影响排班数量。

点击姓名旁的「编辑姓名」可修改有头像或无头像的主播档案。保存时同步修改所有匹配旧姓名的主播排班，并保留原档案和照片。新姓名如已被其他档案或排班使用，页面会要求改成可区分的姓名。后续录入排班时请填写新姓名。

点击「删除主播」并确认后，档案和头像会从头像库移除。关联排班继续保留主播姓名，展示页显示头像占位。之后导入排班时会跳过该档案的自动创建，手动以同一姓名上传头像可重新建立档案。

界面沿用现有管理员页的白色磨砂玻璃视觉风格。

## 3. 一次性批量上传

管理员可拖拽或多选 JPG、PNG 文件。推荐以文件名识别主播，例如：

- 张思琪.jpg
- 王晓.png
- 主播编号A102_林悦.jpg（自动取下划线后的“林悦”，提交前可编辑）

上传后先显示确认清单，不立即保存：

| 文件 | 识别出的主播 | 处理方式 |
| --- | --- | --- |
| 张思琪.jpg | 张思琪 | 新建头像 |
| 王晓.png | 王晓 | 替换现有头像，显示替换提示 |
| A102_林悦.jpg | 林悦 | 取下划线后的文件名作为姓名 |

管理员可在确认页修改姓名，再一次性提交。若同一批次姓名重复、主播已有照片或图片格式不支持，页面指出问题并要求处理；不会静默覆盖已有头像。

首版图片规则：JPG/PNG，单张不超过 8 MB，单次最多 20 张且合计不超过 28 MB。保存后显示新增和更新数量；校验失败时保留未提交队列。

## 4. 主播身份与排班关联

头像必须绑定到主播身份，不能只靠“当前排班行”保存，否则同一主播出现在不同直播间时仍要重复上传。

当前主播标识规则：

- 系统为姓名生成稳定档案 ID。
- 当前版本按规范化姓名精确匹配头像档案；主播编号、别名和同名消歧尚未实现，因此同名主播应使用一致且能区分的排班姓名。
- 未建档的主播仍可排班，但预览提示头像缺失；排班提交后展示页使用该时段已有照片或无头像占位。

员工日常只需在 MCP 文案里填写主播姓名。头像已在库中时，系统自动关联，无需在对话里再发图片。

## 5. MCP 写入流程

现有预览和确认流程保持不变：

1. MCP 根据排班中的主播姓名查找主播档案。
2. 预览列出每个时段的头像状态：头像库、该时段已有照片或未配置。
3. 员工确认完整排班预览后，MCP 提交排班。
4. 展示页按当前时段读取关联主播头像，并自动刷新。

“未上传头像”作为提醒，不阻止排班提交。MCP 返回头像是否存在及来源，不直接向普通员工暴露图片数据。

当前 Harness 对话里的图片附件不会自动传进 MCP。首版头像新增和替换由管理员在头像库上传；员工通过 MCP 更新排班即可使用库中已有头像。

## 6. 数据存储与现有数据兼容

已实现版本使用 SQLite 的 `host_avatars` 表统一保存主播姓名、规范化姓名键、图片类型、图片内容、图片摘要和更新时间；旧排班照片继续留在 `slots.photo_type/photo_blob`，作为兼容回退。当前按 NFKC 规范化、去除空白并忽略大小写后的主播姓名自动关联，没有独立主播编号或别名字段。

服务启动时会扫描已有排班照片。同一姓名只有一张唯一图片时自动加入头像库；同一姓名存在多张不同图片时不会自动选图，管理员页会列出冲突，原排班仍使用各自旧照片。管理员上传头像后，展示页优先使用头像库照片；移除头像时该姓名显示无头像占位，避免旧排班图片意外重新出现。

## 7. Excel 兼容规则

现有 Excel 中嵌入的主播照片继续可识别。工作簿上传时，如果某个新主播的所有排班照片一致，照片会自动作为该主播的头像库初始照片；同一主播存在多张不同照片时保留行内照片，不自动挑选。头像库已有照片不会被 Excel 行内照片覆盖，统一更换需到“主播头像库”明确操作。Excel 原有行内照片锚点和表格格式仍按当前模板规则执行。

## 8. 权限与安全

- 只有管理员可以查看和管理头像库、上传、替换、停用或删除头像。
- 普通用户只能在直播间展示页看到当前主播头像。
- 图片继续保存在服务器私有 SQLite 数据中，通过登录保护的图片接口读取，不生成公开地址。
- 移除头像会先提示影响的排班数量；主播档案保留，排班仍可继续使用。
- 图片继续保存在私有 SQLite 数据中，通过登录保护的图片接口读取；上传限制为 JPG/PNG、单张 8 MB、一次最多 20 张。

## 9. 验收标准

- 管理员能一次选择多张图片，逐项确认姓名匹配后批量入库。
- 管理员能随时搜索主播、查看头像大图、查看被排班引用数量并更换或移除照片。
- MCP 写入已建档主播的排班后，展示页能自动显示头像；同一主播跨直播间和时段复用同一照片。
- 图片缺失或姓名重复时，预览明确提示，系统不误关联。
- 替换头像后，所有关联排班的展示页在自动刷新后显示新图。
- 迁移失败或 Excel 校验失败时，现有排班和照片保持可用。

## 10. 后续可扩展项

本次开发落地了管理员头像库、批量上传/搜索/预览/更换/移除、历史照片自动迁移、排班与展示接口按主播姓名匹配，以及 MCP 头像缺失提示。主播编号、艺名/别名、操作审计、逐条查看引用排班、人工处理历史冲突图、MCP 图片附件上传可后续迭代。
