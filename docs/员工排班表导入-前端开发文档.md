# 员工排班表按直播间名称导入 · 前端开发文档

- 状态：已实现
- 入口：管理端 → 排班 Excel
- 适用范围：管理员上传一份员工排班表，一次处理其中出现的直播间和日期。

## 1. 页面入口

「导入员工排班表」逐页读取员工使用的 .xlsx。每位负责人可以填写一个工作表，每张表可以有多个直播间和日期。空工作表和只有表头的工作表会跳过，房间和日期的继承范围限于当前工作表。

~~~text
排班 Excel
┌─ 导入员工排班表 ──────────────────────────────────┐
│  上传员工排班表，按表内直播间和日期导入。          │
│  [选择 .xlsx 文件，最大 30 MB]    [校验并预览]    │
└─────────────────────────────────────────────────┘
~~~

## 2. 上传与直播间匹配

1. 选择文件后显示文件名和大小，启用「校验并预览」。继续使用单文件上传。
2. 服务端读取「直播间名称」（兼容旧表的「直播间」）和「直播间号码」。优先匹配已登记的名称或别名。房号不一致时，预览列出表内编号及实际归入的房号。未登记名称填了已被占用的房号时，由管理员确认归属。只填号码的行按系统当前房号匹配，支持 `8`、`08` 和 `8号直播间`。
3. 所有房间匹配且校验通过时直接进入预览。同名数据跨日期、跨工作表汇总。未登记的新名称填写了多个编号，或现有重名房间无法自动确定编号时，先展开「匹配直播间」选择一项。
4. 每个待匹配项显示「表内名称、首次出现的工作表和行号、涉及日期数」。下拉框展示 01–27 号及后台名称。未创建的编号显示「08 号 · 未录入」，已创建的显示「08 号 · 后台名称」。
5. 选中已创建的直播间时，把该表内名称登记为其别名。选中未创建的编号时，使用表内名称建立直播间。新直播间按候选编号排序并接在现有列表末尾，预览显示最终房号。建立记录和保存别名都发生在最终确认写入时。
6. 「生成预览」在全部名称都有目标且手动选择无冲突时启用。多个表内名称自动匹配到同一编号时，合并其排班，预览显示这些表内名称供核对。

~~~text
匹配直播间
表内名称       来源           涉及日期      对应直播间
直播间 A       Sheet1 第 2 行    4 天       已匹配 · 01 号
直播间 B       Sheet1 第 6 行    4 天       [请选择 01–27 号 ▾]
直播间 C       Sheet1 第 9 行    4 天       [请选择 01–27 号 ▾]

                                         [生成预览]
~~~

「返回修改匹配」保留当前文件和选择，作废当前预览。更换文件时清理旧文件、匹配结果和预览。

## 3. 导入预览

### 3.1 预览结构

- 顶部汇总直播间数、日期范围、房间日期组合数、主播场数、导演班数和跳过项数。直播间数按房间编号去重，日期从单元格读取。
- 按直播间分组。房间标题显示「编号 · 后台名称」，新建房间标记「首次录入」。每个房间内按日期升序列出预览。
- 每天显示「主播 原有 → 导入后」和「导演 原有 → 导入后」两组数量。展开日期后，主播和导演各用时间列表，分别展示姓名、时段、跨日结束日期及来源行。主播场次同时展示助播、主推商品和目标销售额。
- 当某一类从有排班变为 0 时，用明确文案显示「当天导演排班将清空」或「当天主播排班将清空」。当天某一类为 0 时，明细显示「当天无导演排班」或「当天无主播排班」。
- 错误和跳过提示按工作表、行号、日期、房间及角色定位。所有提示可展开查看。页面底部提供「返回修改匹配」「取消」和「确认导入」。

~~~text
导入预览
3 个直播间 · 11 月 19–22 日 · 12 个房间日期组合
33 场主播 · 26 班导演 · 2 项跳过

09 号 · 直播间 C
▾ 11 月 21 日    主播 3 → 2 场     导演 1 → 0 班
  主播排班                           导演排班
  2 场，按时间展开                   当天导演排班将清空

                    [返回修改匹配] [取消] [确认导入]
~~~

线框中的旧数据数量仅用于演示预览样式。实际数量由服务端查询。

### 3.2 表格数据如何反映在预览中

| Excel 情况 | 预览和写入规则 |
| --- | --- |
| 日期或直播间只写在分组首行 | 服务端继承当前工作表内的当前组；遇到新日期重新读取房间名称或号码 |
| 同一行导演和主播时段不同 | 分别加入对应列表，按各自时段排序。同房间、同角色才做重叠校验 |
| 同一编号和日期重复填写完全相同的班次 | 保留首次出现的班次并提示重复来源。其他同角色时段重叠会阻止提交 |
| 某角色有时间、没有姓名 | 跳过该角色的这项安排，提示来源位置；同一行另一个角色照常处理 |
| 某角色有姓名、缺时间或时间无效 | 定位到时间单元格，阻止整次提交 |
| 20:00–00:30 一类跨午夜时段 | 预览显示「20:00–次日 00:30」，按开始日归属，和相邻日期的同角色排班一起校验 |
| 某房间某天只有一类角色有班次 | 这一天纳入更新，另一类按 0 预览；空档不生成排班 |
| 某房间某天两类都没有有效班次 | 列为跳过项，保留该日已有排班。空白行不构成删除指令 |
| Excel 中的「星期」「休」列 | 日期以「日期」列为准。「休」供员工排班参考 |
| Excel 中的「助播」「助播时间」列 | 助播随同一行主播录入。助播时间可留空，填写时须与主播时段一致 |
| 「主推商品」和「目标销售额」 | 填在主播场次所在行。商品用英文逗号 `,` 或中文逗号 `，` 分隔。目标销售额作为原文本保存和展示。只有导演的行会提示并跳过这两列 |
| 已有相同房间、日期、起止时间和主播 | 助播留空时沿用原助播，同时沿用原备注和照片。旧表缺少商品或目标销售额列时，对应资料沿用原值。新表列存在但单元格留空时，对应值清空 |

确认后按「房间编号 × 排班开始日期」整体替换预览所列的两类排班。若同一间、同一天由不同人上传，后一次已确认的完整排班会替换前一次。预览中同时展示原有数量和本次日期范围，供管理员核对。

## 4. 页面状态和异常处理

| 状态 | 页面行为 |
| --- | --- |
| 未选文件 | 「校验并预览」禁用，使用现有文件控件 |
| 正在校验 | 显示「正在读取排班表…」，防止重复请求 |
| 需匹配房间 | 展开匹配区，缺少选择时定位到对应下拉框 |
| 表格有错误 | 保留文件名并给出具体行列。允许更换修正后的文件 |
| 可确认 | 展示最终预览。确认按钮仅接受当前文件和匹配结果对应的预览 |
| 正在导入 | 禁用更换文件、改匹配、重复确认及取消 |
| 预览失效 | 保留本次文件和选择，显示「排班或直播间资料已更新，请重新生成预览」并清除提交凭证 |
| 校验请求失败 | 保留文件和匹配选择，允许重新校验 |
| 提交请求断开 | 显示「暂未收到导入结果」，用原凭证查询结果或重试。服务端返回同一提交的结果，避免重复写入 |
| 导入成功 | 显示直播间数、日期范围、分角色数量，提供「查看已录入排班」和「继续导入」 |

页面退出时中止浏览器请求，忽略迟到的响应。成功后的「查看已录入排班」打开现有记录页。已结束的时段可从「已归档」展开查看。

## 5. 前端落地位置

| 文件 | 改动 |
| --- | --- |
| `src/App.jsx`、`src/staff-import.jsx` | 「排班 Excel」通过独立组件处理文件、名称匹配、预览与提交 |
| `src/styles.css` | 沿用管理卡片、文件选择、错误提示和按钮样式。为房间匹配、按日期展开与角色列表增加布局 |
| `server.mjs`、`server/staff-schedule.mjs`、`server/xlsx.mjs` | 解析员工表，按名称匹配，生成预览并提交 |

桌面端的匹配项按行展示。手机端把「表内名称 → 对应房间」纵向排列，主播与导演列表也纵向排布。日期明细可用原生 `details` 展开，直播间匹配使用有标签的原生 `select`。错误同时显示文字和状态色，支持键盘及深色模式。

## 6. 联调接口

使用管理员权限和 CSRF 校验。Excel 导入使用 `mode=room-name`。

| 操作 | 请求 | 返回与前端处理 |
| --- | --- | --- |
| 校验或重新预览 | `POST /api/v1/admin/schedule-upload?action=preview&mode=room-name`。使用 multipart，传 `file`，已选择的对应关系通过可选 `roomBindings` JSON 字段发送 | 初次识别返回 `needs_mapping` 或 `ready`。待匹配返回各名称和来源位置。重新预览可重用前端选中的文件 |
| 读取候选房间 | 预览响应内的 `roomOptions`，也可调用 `GET /api/v1/admin/schedule-upload/rooms` | 返回 01–27 号和后台名称。未录入的编号名称为 `null` |
| 确认导入 | `POST /api/v1/admin/schedule-upload?action=commit&mode=room-name`。JSON 传 `previewId` | 返回本次写入统计。版本变化、凭证过期或匹配失效时返回 409 |

预览响应至少包含以下字段。

- `sourceRooms`：`sourceRoomKey`、表内名称、首次出现的工作表和行号、匹配状态、后端匹配的房间编号。
- `rooms`：目标编号、后台名称、是否新建和各日期预览。每天包含 `hostShifts`、`directorShifts`、原有数量及替换后的数量。时段包含统一格式的开始、结束、跨日信息和来源行。
- `errors`、`warnings`：工作表、行号、列或字段、房间、日期和给用户的说明。阻断问题使用 422。跳过项可与成功的预览同时返回。
- `summary`：去重后的房间数、日期范围、房间日期组合数、两类时段数量及跳过项数。
- `previewId`：仅在 `ready` 返回。服务端绑定管理员、已校验的排班内容、房间对应关系和数据版本。提交时重新验证，并在同一事务写入新房间、别名和排班。超时重试可返回原提交结果。

## 7. 验收用例

| 用例 | 期望结果 |
| --- | --- |
| 上传实际样表，完成 3 个房间的匹配 | 预览日期为 **2026-11-19 至 2026-11-22**，共 **3 间、12 个房间日期组合、33 场主播、26 班导演**。「有时间没姓名」提示共 2 项。带商品和销售额的样表另有 2 行商品资料没有对应主播 |
| 样表中第三个直播间的 11 月 21 日 | **主播 2 场、导演 0 班**。若已有导演排班，预览显示当天将清空导演 |
| 已知房间再次上传 | 名称自动关联，直接进入预览。首次绑定在取消后仍待匹配，确认成功后才记住 |
| 两个员工先后上传各自负责的直播间 | 各自预览和提交只包含自己文件的房间日期组合 |
| 同时上传一间的多天安排 | 所有实际日期一次预览和确认。文件名所写日期范围与单元格不一致时，以单元格为准 |
| 同角色跨午夜班次与次日冲突 | 标出冲突时段和来源。导演与主播互相交叉仍可导入 |
| 选择错误的房间后回退修改 | 当前预览作废，确认按钮锁定直到生成新预览 |
| 预览后同一天排班被他人更新 | 返回 409，要求重新查看预览和将替换的数量 |
| 提交旧单间或总表接口参数 | 返回 400，并提示刷新后使用员工排班表导入 |

样表用于本地验收。开发文档使用房间代称，测试夹具可使用虚构姓名。
